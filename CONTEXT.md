# Software Factory

The SoftNext shared configuration layer for running Sandcastle-driven agent loops across projects. This repo holds the *Factory* — the converged process and orchestration knowledge — so any project can clone it to start, instead of reassembling a Sandcastle setup by hand.

## Language

### Layering

**Sandcastle (the Engine)**:
The upstream TypeScript runtime/CLI (`mattpocock/sandcastle`, npm `@ai-hero/sandcastle`) that orchestrates Docker/Podman sandboxes, git worktrees, and agent sessions. An external pinned dependency of the Factory — never vendored or forked.
_Avoid_: the runtime, the CLI (when ambiguous), Sandcastle-as-our-thing.

**The Factory**:
This repo — the converged config-and-orchestration layer a project clones to run a Sandcastle loop. Config only; it contains no Engine code.
_Avoid_: Sandcastle (the Engine is upstream, the Factory is our layer).

**Factory instance**:
A project's clone-and-own copy of the Factory (its `.sandcastle/` + `.claude/` config). It drifts freely after cloning; the Factory is the reference it was cloned from.
_Avoid_: deployment, installation.

**Adoption**:
The act of bringing the Factory into a repo that already has its own history and remote — the in-place counterpart to the greenfield clone. Performed by `.sandcastle/adopt.ts`, which copies the tracked `.sandcastle/` config layer, wires the Engine and dev tools into the consumer, ships a self-contained ESM shim (`.sandcastle/package.json` with `{"type":"module"}`) so `main.ts` transpiles regardless of the consumer's root `package.json`, and stages the config layer into the consumer's git — a tracked, scoped `.sandcastle/.gitignore` keeps only the runtime artifacts (`.env*`, `logs/`, `worktrees/`, the Engine install) out, without editing the consumer's committed root `.gitignore`. The result is a Factory instance that drifts from the reference exactly like a greenfield clone.
_Avoid_: submodule (adoption is clone-and-own, not a linked submodule), vendor (the Engine stays an npm dependency).

**Project context**:
The per-project content that lives in the consumer, never in the Factory: the project-specific sections of `CLAUDE.md` and the project's own domain `CONTEXT.md` (both shipped as fill-in skeletons under `templates/`), and `settings.local.json` (per-developer local permissions, gitignored, generated by Claude Code — consumer-local, not shipped).
_Avoid_: config (too generic).

### The Orchestration

**The Orchestration**:
The custom `.sandcastle/main.ts` loop that drives the Engine with discrete agent roles. The core artifact the Factory converges.
_Avoid_: the loop, the pipeline (when ambiguous).

**Agent role**:
One of the discrete participants in the Orchestration: Planner, Implementer, Reviewer, and (optionally) Merger. Each runs in its own sandbox or worktree under a chosen provider.

**Merger**:
The optional fourth agent role that merges implemented work. Present only under `MERGE_STRATEGY=agent`; absent when a human reviews draft MRs.
_Avoid_: auto-merge (that is a behaviour, not the role).

### Modes

**Split**:
A regime where the Implementer runs on GLM (z.ai) and the Reviewer on Claude Opus (Anthropic), enforcing the invariant that the reviewer never shares the implementer's blind spots. Cross-provider by construction.
_Avoid_: dual-model, ensembling.

**Opus**:
A regime where all agent roles run on Opus, for high-stakes tickets. Selected by `SANDCASTLE_PROFILE=opus`.
_Avoid_: full-opus, all-Claude.

**Chained**:
A mode that stacks merge requests instead of fanning them: ticket N forks from the head of N-1's draft MR pile, so each MR's diff shows only its own ticket. Exists to keep long EPICs reviewable when the loop outpaces human review. Toggled by `SANDCASTLE_CHAIN=1`.
_Avoid_: stacking (informal), serial mode.

**Profile**:
A named regime the Orchestration runs under, selected by `SANDCASTLE_PROFILE`. Each profile fixes the provider and reasoning effort for every role. Provider follows profile; effort follows provider.
_Avoid_: preset, configuration (too generic).

### Configuration & Skills

**MERGE_STRATEGY**:
The first-class config option encoding who merges implemented work: `agent` (a Merger role auto-merges) or `human` (draft MRs await human review). Captures the two process philosophies the Factory must support.

**skills-lock.json**:
The manifest of record for the Matt Pocock skills vendored into the Factory — each skill's source, path, and content hash — so the vendored versions are known and updatable.
_Avoid_: lockfile (ambiguous), package manifest.

**Vendored skill**:
A skill authored upstream (the Matt Pocock suite) and copied into the Factory's `.claude/skills/`. It has an upstream, so it is hashed in `skills-lock.json` and `npm run skills:check` rules on its drift; editing one in place is tampering, not maintenance. Updating means re-fetching from upstream and regenerating the lock.
_Avoid_: our skills, installed skill.

**Own skill**:
A skill the Factory writes itself, living in the top-level `skills/` directory (flat: `skills/<name>/SKILL.md`) — outside the lock's scan, because it has no upstream to drift from ([ADR-0006](docs/adr/0006-own-skills-live-outside-the-lock-scan.md)). Its body is French; it is installed on a workstation by hand into `~/.claude/skills/`, and ships to no consumer.
_Avoid_: custom skill, local skill, vendored skill (an own skill has no upstream).
