# The Factory boundary — universal orchestration in, project context out

**Status**: Accepted (2026-08-04)

The Factory contains only universal process and orchestration knowledge: the converged `main.ts`, the mode mechanisms (Split, Opus, Chained, Merger), the vendored skills, and the workflow docs. Project-specific context stays in the consumer: the project's own `CLAUDE.md` sections and its domain `CONTEXT.md` ship as **fill-in skeletons** (`templates/`); `settings.local.json` is per-developer local permissions — gitignored and generated by Claude Code itself as permissions are granted, so it is consumer-local and **not** shipped as a skeleton. The line matters because over-merging project context contaminates the shared Factory, and under-merging leaves the drift we are trying to kill.

Tuning and model-profile *documents* (e.g. `sandcastle-model-profiles.md`, token-tuning runbooks) are treated as project experiments and kept OUT for now; only the *mechanisms* they describe (profiles, Split) are universal Factory features.
